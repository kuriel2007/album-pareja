Preparar nuestro rincón.

Configuración inicial: ejecuta el SQL de abajo en el SQL Editor de tu proyecto y añade su clave pública. Hazlo una sola vez; en otro dispositivo basta con guardar la misma clave pública.

Nunca pegues una clave service_role ni una secret. La privacidad real depende de las políticas RLS incluidas abajo, no de esconder la clave pública.

1. SQL para proteger mensajes y fotografías

Autoriza únicamente los dos UID de tus usuarios actuales. Si recreas una cuenta, cambia su UID aquí. Este script utiliza tablas nuevas llamadas couple_messages y couple_photos.

-- Ejecutar en el proyecto mmoaxgeqvrsnzcsxxnjs.
-- Ambos usuarios deben existir en Authentication > Users.

create or replace function public.is_couple_member()
returns boolean
language sql stable
set search_path = ''
as $$
  select auth.uid() in (
    'b62b7adb-29ce-443b-ba3b-fa9904a7d1cf'::uuid,
    'feae3f03-6773-4c88-ad35-af834405b4b4'::uuid
  );
$$;

revoke all on function public.is_couple_member() from public;
grant execute on function public.is_couple_member() to authenticated;

create table if not exists public.couple_messages (
  id uuid primary key default gen_random_uuid(),
  sender_id uuid not null references auth.users(id),
  body text not null check (length(trim(body)) between 1 and 4000),
  created_at timestamptz not null default now()
);

create table if not exists public.couple_photos (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references auth.users(id),
  title text not null check (length(trim(title)) between 1 and 120),
  meeting_date date not null,
  storage_path text unique not null,
  created_at timestamptz not null default now(),
  constraint photo_owner_path check (
    split_part(storage_path, '/', 1) = owner_id::text
  )
);

alter table public.couple_messages enable row level security;
alter table public.couple_photos enable row level security;

revoke all on public.couple_messages, public.couple_photos from anon;
revoke all on public.couple_messages, public.couple_photos from authenticated;
grant select, insert on public.couple_messages to authenticated;
grant select, insert, delete on public.couple_photos to authenticated;

drop policy if exists couple_messages_read on public.couple_messages;
create policy couple_messages_read on public.couple_messages
for select to authenticated using (public.is_couple_member());

drop policy if exists couple_messages_write on public.couple_messages;
create policy couple_messages_write on public.couple_messages
for insert to authenticated with check (
  public.is_couple_member() and sender_id = auth.uid()
);

drop policy if exists couple_photos_read on public.couple_photos;
create policy couple_photos_read on public.couple_photos
for select to authenticated using (public.is_couple_member());

drop policy if exists couple_photos_write on public.couple_photos;
create policy couple_photos_write on public.couple_photos
for insert to authenticated with check (
  public.is_couple_member() and owner_id = auth.uid()
);

drop policy if exists couple_photos_delete on public.couple_photos;
create policy couple_photos_delete on public.couple_photos
for delete to authenticated using (
  public.is_couple_member() and owner_id = auth.uid()
);

insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values (
  'couple-memories', 'couple-memories', false, 10485760,
  array['image/jpeg','image/png','image/webp']
)
on conflict (id) do update set
  public = false,
  file_size_limit = 10485760,
  allowed_mime_types = array['image/jpeg','image/png','image/webp'];

drop policy if exists couple_storage_read on storage.objects;
create policy couple_storage_read on storage.objects
for select to authenticated using (
  bucket_id = 'couple-memories' and public.is_couple_member()
);

drop policy if exists couple_storage_upload on storage.objects;
create policy couple_storage_upload on storage.objects
for insert to authenticated with check (
  bucket_id = 'couple-memories'
  and public.is_couple_member()
  and (storage.foldername(name))[1] = auth.uid()::text
);

drop policy if exists couple_storage_delete on storage.objects;
create policy couple_storage_delete on storage.objects
for delete to authenticated using (
  bucket_id = 'couple-memories'
  and public.is_couple_member()
  and (storage.foldername(name))[1] = auth.uid()::text
);

create index if not exists couple_messages_created_idx
on public.couple_messages(created_at);
create index if not exists couple_photos_date_idx
on public.couple_photos(meeting_date);

Si ya existen otras políticas en estas tablas o en Storage, revisa que no concedan acceso adicional. Las políticas permisivas se combinan con OR.

2. Si aparece «correo o contraseña incorrectos»

En Authentication → Users, asegúrate de que las dos cuentas tengan contraseña y correo confirmado. «Email Enabled» no garantiza que exista una contraseña. Si no la recuerdas, usa Enviar recuperación de contraseña y el flujo de recuperación configurado para tu proyecto; no borres los usuarios, porque sus UID protegen este espacio.

Esta página usa signInWithPassword, no magic link. No ofrece registro público. Puedes asignar una contraseña desde un entorno administrativo seguro con auth.admin.updateUserById; nunca uses la clave administrativa en este HTML.

3. Publicar la página

Guarda este archivo como index.html y publícalo en un hosting HTTPS como Netlify, Vercel o GitHub Pages. Agrega su dirección en Authentication → URL Configuration. No compartas dispositivos sin cerrar sesión. El HTML es público; los datos están protegidos por Supabase.
